# 데이터 관리 원칙 및 명명 규칙 (Data Management)

* **갱신 일시**: 2026년 10월 5일

본 문서는 마비노기 모바일 헬퍼 시스템에서 생성 및 관리하는 데이터의 동기화 원칙, 문서 구조, 명명 규칙을 정의합니다.

---

## 1. 캐릭터 정보 수집 및 정합성 관리

* **캐릭터 정보 수집 방식**:
  * 한 계정 내에는 서버당 최대 6개(`MAX_CHARACTERS_PER_SERVER`)의 캐릭터가 존재할 수 있습니다.
  * AI 커넥터 특성상 한 번에 접속 중인 하나의 캐릭터 정보만 조회 가능하므로, 사용자에게 각 캐릭터별 접속을 유도하여 개별적으로 정보를 수집합니다.
  * **(중요)** 커넥터 API에서 캐릭터 이름(닉네임)을 반환하지 않으므로, 정보 수집 시 항상 **사용자에게 현재 접속 중인 캐릭터명이 무엇인지 확인 요청**해야 합니다.
* **계정 캐릭터 정합성 관리**:
  * 서버 및 계정 내 실제 보유 중인 캐릭터 수를 별도로 파악하여 관리합니다.
  * 수집된 캐릭터 문서 수와 실제 캐릭터 수가 다를 경우, 사용자에게 나머지 캐릭터로의 접속 및 정보 갱신을 요청/권장합니다.
* **최종 갱신 일시 표기 및 데이터 신선도 관리**:
  * 데이터 정합성을 확인하기 위해 각 캐릭터 데이터마다 **최종 갱신 일시**를 명시합니다.
  * 재고 정보의 경우, CSV 파일 내부 대신 `(서버명)_(캐릭터명).md` 문서 내에 각 CSV 파일별 최종 업데이트 일시를 기록하여 관리합니다.
* **오래된 타 캐릭터 상태 처리 원칙**:
  * 저장된 다른 캐릭터의 상태(`최종 갱신 일시`)가 너무 오래된 경우(기본 3일 초과 등 `OTHER_CHAR_STALE_DAYS` 만료 시), 재고 확인에는 참고용으로만 사용하고, 채집 시 부족분 계산 및 보류 판정에는 반영하지 않습니다(즉, 보류하지 않고 부족분으로 산출하여 채집 대상에 포함).
* **상태 유지 원칙**:
  * 변경 이력(diff)은 별도로 관리하지 않으며, 문서는 항상 **최신 상태로 덮어쓰기**합니다.

## 2. 데이터 시트 구조 및 우선순위

* **사용자 정의 특수 규칙 (`workflows_custom.md`)**:
  * 스킬을 사용하는 사용자가 개별적으로 정의한 특수 동작 규칙입니다.
  * `data/` 폴더 내에 `workflows_custom.md`가 존재할 경우, API 응답 다음으로 우선 적용(2순위)되며 스킬의 기존 기본 동작이나 워크플로우를 무시하거나 변경하여 동작합니다.
* **캐릭터 정보 디렉토리 (`characters/`)**:
  * 캐릭터 관련 모든 정보(상세 상태, 인벤토리, 금고, 퀘스트, 요약 색인)를 통합 관리하는 디렉토리입니다.
  * **통합 요약 색인 (`characters/README.md`)**: 계정 내 모든 캐릭터들의 핵심 정보(직업, 전투력, 생활력, 갱신일)를 한눈에 볼 수 있는 요약 색인 시트입니다.
  * **개별 캐릭터 시트 (`characters/(서버명)_(캐릭터명).md`)**: 각 캐릭터의 상세 스탯, 점수, 상태를 하나의 시트로 분리하여 유지합니다.
  * **인벤토리 및 금고 데이터 (`characters/*.csv`)**: 캐릭터별 가방, 개인 금고 및 서버 공용 금고 CSV 파일입니다.
  * **퀘스트/미션 데이터 (`characters/(서버명)_(캐릭터명)_quest.md`)**: 캐릭터별 진행 중인 퀘스트와 일일/주간 미션 현황입니다.
* **재고 목표치 관리 (`target_*.md`)**: 관리 대상 아이템의 목표치를 마크다운 테이블로 관리합니다.
  * **채집 재고 목표치 (`target_gathering.md`)**: 채집물 목표 수량 관리
  * **가공 재고 목표치 (`target_altering.md`)**: 가공 결과물 목표 수량 관리
* **레시피 관리 (`recipe_*.md`)**: 시설별 레시피 및 필요 재료 정보를 마크다운 테이블 형태로 관리합니다.
  * **가공 레시피 (`recipe_altering.md`)**: 가공 시설별 결과물, 필요 재료 및 생산 수량 관리 (일괄 가공 연동)
  * **제작 레시피 (`recipe_crafting.md`)**: 제작 시설별 레시피 및 필요 재료 관리 *(일반 제작 명령 시 참고용)*
* **챗봇 지식베이스 (`chatbot/`)**:
  * 인게임 공략, 팁, 채집/제작 방법 등을 관리하는 지식 저장소입니다.
  * `chatbot/README.md`에 전체 지식 문서의 색인(Index)과 태그 목록을 유지합니다.
  * 개별 문서는 `chatbot/(주제명).md` 형태로 생성되며, 상단에 `#태그`를 포함하여 키워드 검색 시 활용됩니다.
  * 사용자가 직접 작성한 정보와 인터넷 검색으로 수집된 정보가 함께 통합 관리됩니다.
* **동작 및 판단 우선순위**:
  1. **API 응답** (최우선 적용)
  2. **사용자 정의 특수 규칙 (`data/workflows_custom.md`)** (2순위 적용)
  3. **유저의 명령**
  4. **로컬 프로젝트 내 저장된 내용 및 기본 스킬 동작**

## 3. 파일 명명 규칙 (Naming Convention)

모든 데이터 문서는 `data/` 디렉토리 하위에 위치합니다.

| 파일명 | 설명 | 포맷 |
| :--- | :--- | :---: |
| `environments.json` | CLI 도구 경로, 실행 환경, 기본 캐릭터/서버 및 규칙 통합 설정 (명세: `references/environments.md`) | JSON |
| `know-how.md` | 시스템 종속적인 도구 사용 노하우 및 가상환경 실행법 | Markdown |
| `TODO.md` | 프로젝트 작업 대기열 및 정합성 점검 대시보드 | Markdown |
| `workflows_custom.md` | 사용자가 개별 정의한 특수 규칙 문서 (API 응답 다음 2순위 적용) | Markdown |
| `characters/README.md` | 계정 내 모든 캐릭터의 요약 정보 및 색인 시트 (구 `characters.md`) | Markdown |
| `characters/(서버명)_(캐릭터명).md` | 개별 캐릭터 상세 정보 및 연관 데이터 갱신 일시 | Markdown |
| `characters/(서버명)_(캐릭터명)_inventory.csv` | 해당 캐릭터의 인벤토리 아이템 목록 | CSV |
| `characters/(서버명)_(캐릭터명)_bank.csv` | 해당 캐릭터 전용 개인 보관함(금고) 아이템 목록 | CSV |
| `characters/(서버명)_bank_all.csv` | 계정 내 동일 서버 캐릭터들이 공유하는 공용 보관함 아이템 목록 | CSV |
| `characters/(서버명)_(캐릭터명)_quest.md` | 해당 캐릭터의 퀘스트 및 일일/주간 미션 진행 상태 | Markdown |
| `target_gathering.md` | 채집 아이템별 재고 목표치 설정 문서 | Markdown |
| `target_altering.md` | 가공 결과물별 재고 목표치 설정 문서 | Markdown |
| `recipe_altering.md` | 가공 시설별 레시피 및 필요 재료 정보 문서 (일괄 가공 연동) | Markdown |
| `recipe_crafting.md` | 제작 시설별 레시피 및 필요 재료 정보 문서 (일반 제작 참고용) | Markdown |
| `chatbot/README.md` | 챗봇 지식 문서 전체 색인(Index) 및 태그 목록 | Markdown |
| `chatbot/(주제명).md` | 개별 게임 공략 및 가이드 지식 문서 (상단 `#태그` 포함) | Markdown |
| `response/(명령어).json` | CLI 명령어 실행에 대한 응답 결과 저장 파일 | JSON |
